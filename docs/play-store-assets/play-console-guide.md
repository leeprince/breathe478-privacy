# Google Play Console 上架完整指南

> 适用应用：深呼吸 (Breathe478)  
> 包名：com.huangzi.breathe478  
> 适合人群：第一次使用 Play Console 的开发者

---

## 前置准备

在开始之前，确认以下内容已就绪：

- Google Play 开发者账号（需支付 $25 一次性注册费）
- AAB 文件：`build\app\outputs\bundle\release\app-release.aab`
- 应用图标：512×512 PNG
- 特色图片：1024×500 PNG
- 手机截图：至少 2 张（建议 4 张），尺寸至少 1080×1920
- 隐私政策 URL：`https://leeprince.github.io/breathe478-privacy/`

> **重要提示**：Play Console 页面操作较多，每个部分填完后务必点击"保存"按钮。页面长时间不操作可能超时，建议每隔 15 分钟保存一次。

---

## 第一步：创建应用

1. 登录 [Google Play Console](https://play.google.com/console)
2. 点击左上角"**所有应用**"，然后点击"**创建应用**"
3. 填写以下字段：

| 字段 | 填写内容 |
|------|----------|
| 应用名称 | 深呼吸 |
| 默认语言 | 中文（简体）|
| 应用或游戏 | 应用 |
| 免费或付费 | 免费 |

4. 勾选两个声明复选框（开发者计划政策、美国出口法律）
5. 点击"**创建应用**"

创建成功后，你会进入应用的管理页面。左侧导航栏包含所有需要填写的部分。

---

## 第二步：应用内容（政策合规）

这是最容易出错的部分，也是审核最严格的地方。左侧导航找到"**政策**" → "**应用内容**"，逐项完成。

> **注意**：每个子项填完后都有独立的"保存"按钮，不要遗漏。

### 2.1 隐私权政策

- 点击"**隐私权政策**"
- 在 URL 输入框填入：`https://leeprince.github.io/breathe478-privacy/`
- 点击"**保存**"

### 2.2 广告

- 点击"**广告**"
- 选择：**否，我的应用不含广告**
- 点击"**保存**"

### 2.3 应用访问权限

- 点击"**应用访问权限**"
- 选择：**应用的所有功能均可使用，无需任何特殊访问权限**
- 点击"**保存**"

（深呼吸不需要登录，所有功能直接可用，选这个选项即可。）

### 2.4 内容分级

内容分级需要填写一份问卷，Google 会根据你的回答自动生成分级结果。

1. 点击"**内容分级**"
2. 点击"**开始问卷**"
3. 填写联系邮箱：`leeprince@foxmail.com`
4. 选择应用类别：**实用工具**（Utility）

> 注意：虽然应用是健康类，但问卷类别选"实用工具"可以避免不必要的额外问题。

5. 接下来的问卷，**所有问题全部选"否"**：

| 问题 | 回答 |
|------|------|
| 是否含有暴力内容？ | 否 |
| 是否含有性暗示内容？ | 否 |
| 是否含有语言暴力？ | 否 |
| 是否含有赌博内容？ | 否 |
| 是否含有毒品/酒精相关内容？ | 否 |
| 是否含有恐怖内容？ | 否 |
| 是否允许用户互动或分享内容？ | 否 |
| 是否含有数字购买？ | 否 |

6. 点击"**保存问卷**"，然后点击"**计算分级**"
7. 确认分级结果（应为"适合所有人"），点击"**应用分级**"

### 2.5 目标受众

- 点击"**目标受众**"
- 选择目标年龄段：**18 岁及以上**
- 系统会问"应用是否专门面向儿童？"→ 选**否**
- 点击"**保存**"

> 选 18+ 可以避免儿童隐私相关的额外审核要求（COPPA 合规等），对于这类放松类应用是最简单的选择。

### 2.6 新闻应用

- 点击"**新闻应用**"
- 选择：**否，这不是新闻应用**
- 点击"**保存**"

### 2.7 数据安全（重点！）

**这是第一次上架最容易卡住的地方。** 很多开发者因为填错这里导致审核被拒。请仔细按照以下步骤操作。

深呼吸应用的数据情况：
- **不收集任何用户数据**（没有账号、没有分析、没有崩溃上报）
- **不分享任何数据**（没有第三方 SDK，没有广告 SDK）
- **没有网络权限**（AndroidManifest.xml 中没有 INTERNET 权限）
- SharedPreferences 存储的设置（音效开关等）**仅保存在本地设备**，不算"数据收集"

**填写步骤：**

1. 点击"**数据安全**"
2. 点击"**开始**"

**第一个问题：您的应用是否会收集或分享任何必填用户数据类型？**
- 选择：**否**

> 说明：SharedPreferences 保存的是应用设置（比如音效是否开启），这是本地存储，不是"收集用户数据"。只有数据被发送到服务器或第三方才算收集。

**第二个问题：您的应用是否使用加密传输数据？**
- 因为选了"否"，这个问题会跳过。

**第三个问题：用户是否可以请求删除其数据？**
- 因为选了"否"，这个问题会跳过。

3. 点击"**保存**"
4. 点击"**提交**"（提交数据安全表单）

填完后，数据安全部分会显示一个摘要，内容大致为"此应用不收集用户数据"。这是正确的。

**常见错误提示：**
- 如果你用了 Firebase、Google Analytics、Facebook SDK 等，必须如实填写，否则会被拒。
- 深呼吸没有用任何第三方 SDK，所以全选"否"是正确的。

### 2.8 政府应用

- 点击"**政府应用**"
- 选择：**否**
- 点击"**保存**"

### 2.9 金融功能

- 所有选项均选**否**（无贷款、无加密货币、无投资功能等）
- 点击"**保存**"

### 2.10 健康功能

- 点击"**健康功能**"
- 选择：**否，这不是医疗应用**
- 点击"**保存**"

> 深呼吸是放松辅助工具，不是医疗设备或诊断工具，选"否"是正确的。

## 第四步：版本发布

### 4.1 推荐流程：先内部测试，再正式发布

**为什么先做内部测试？**
- 内部测试版本审核极快（通常几分钟到几小时）
- 可以在真实设备上验证 AAB 安装正常
- 发现问题可以立即修复，不影响正式审核记录

### 4.2 创建内部测试版本

1. 左侧导航找到"**测试**" → "**内部测试**"
2. 点击"**创建新版本**"
3. 在"**App Bundle**"区域，点击"**上传**"
4. 选择文件：`build\app\outputs\bundle\release\app-release.aab`
5. 等待上传完成（文件约 10-20MB，视网速需要 1-5 分钟）

**填写版本说明（What's new）：**

```
首次发布

· 支持 4-7-8 呼吸、方块呼吸、深呼吸三种模式
· 视觉圆圈引导，震动/铃声提示
· 完全离线，无广告，无数据收集
```

6. 点击"**保存**"，然后点击"**审核版本**"
7. 确认无误后点击"**开始内部测试**"

### 4.3 添加内部测试人员

1. 在内部测试页面，点击"**测试人员**"标签
2. 创建一个测试人员列表，添加你自己的 Gmail 邮箱
3. 复制测试链接，在 Android 手机上打开安装测试

### 4.4 升级到正式发布（生产）

内部测试确认没问题后：

1. 左侧导航找到"**发布**" → "**生产**"
2. 点击"**创建新版本**"
3. 在"**从之前的版本添加**"中，选择刚才的内部测试版本（这样不用重新上传 AAB）
4. 版本说明同上
5. 点击"**保存**" → "**审核版本**" → "**开始发布到生产环境**"

> 正式发布审核通常需要 1-7 天，新开发者账号首次发布可能需要更长时间（最长 14 天）。

## 第五步：发布前检查清单

提交前，Play Console 仪表盘会显示一个检查清单，**所有项目必须变为绿色才能提交**。

常见检查项：

- [ ] 应用内容 → 隐私权政策 ✓
- [ ] 应用内容 → 广告声明 ✓
- [ ] 应用内容 → 内容分级 ✓
- [ ] 应用内容 → 目标受众 ✓
- [ ] 应用内容 → 数据安全 ✓
- [ ] 商品详情 → 应用名称和描述 ✓
- [ ] 商品详情 → 图标 ✓
- [ ] 商品详情 → 截图（至少 2 张）✓
- [ ] 商品详情 → 联系邮箱 ✓
- [ ] 版本 → 已上传 AAB ✓

**常见被拒原因及避免方法：**

| 被拒原因 | 避免方法 |
|----------|----------|
| 隐私政策 URL 无法访问 | 提交前在浏览器打开 URL 确认可以访问 |
| 数据安全填写与实际不符 | 如实填写，深呼吸全选"否"即可 |
| 截图质量差或尺寸不符 | 使用模拟器截图，确认尺寸 ≥ 1080×1920 |
| 应用描述含有误导性内容 | 不要写"最好的"、"第一名"等无法证明的说法 |
| 应用崩溃或功能异常 | 内部测试时在真机上完整测试一遍 |
| 目标受众与内容不符 | 选 18+ 并确保描述中没有针对儿童的内容 |

## 第六步：提交后

### 审核时间

- **内部测试**：几分钟到几小时
- **正式发布（新账号首次）**：3-14 天
- **后续更新**：1-3 天

### 查看审核状态

1. 进入 Play Console → 选择应用
2. 左侧导航"**发布**" → "**生产**"
3. 查看版本状态：
   - "审核中" → 等待
   - "已发布" → 成功，可在 Play Store 搜索到
   - "已拒绝" → 查看拒绝原因

### 如果被拒绝

1. 在 Play Console 首页或邮件中查看拒绝原因（Google 会发邮件到注册邮箱）
2. 根据拒绝原因修改对应内容
3. 如果是应用内容问题，修改后重新提交同一版本
4. 如果是 APK/AAB 问题，修复后重新打包上传新版本
5. 申诉入口：Play Console → 政策状态 → 申诉（如果认为判断有误）

> **常见拒绝原因处理**：
> - "隐私政策不符合要求" → 检查隐私政策 URL 是否可访问，内容是否说明了数据处理方式
> - "数据安全信息不准确" → 重新检查数据安全问卷，确保与实际代码一致
> - "元数据违规" → 检查描述中是否有违禁词（如"免费"、竞品名称等）

## 第七步：发布后更新流程

### 更新步骤

1. 修改代码，在 `pubspec.yaml` 中更新版本号：
   ```yaml
   version: 1.0.1+2  # 格式：版本名+版本号，版本号必须递增
   ```

2. 重新打包 AAB：
   ```
   flutter build appbundle --release
   ```

3. 进入 Play Console → 生产 → 创建新版本
4. 上传新的 AAB 文件
5. 填写更新说明（用中文写本次更新了什么）
6. 提交审核

### 版本号规则

- `version: 1.0.0+1` 中，`1.0.0` 是用户看到的版本名，`+1` 是内部版本号
- 每次上传新 AAB，内部版本号（`+` 后面的数字）**必须比上一次大**，否则无法上传
- 版本名可以不变，但建议有意义的更新时同步更新版本名

### 保持账号活跃

建议每 1-2 个月发布一次小更新（哪怕只是优化描述或修复小问题），原因：
- Google 会对长期不更新的应用降低搜索排名
- 保持与用户的互动，及时回复评论
- 定期检查 Play Console 是否有政策变更通知
